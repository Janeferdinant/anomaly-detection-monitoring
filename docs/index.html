Alert tuning demo

Pick a sensor series, move the threshold and persistence sliders, and watch which alerts a naive detector and an improved detector raise on the same data. Incidents were injected with a seeded generator, so every alert can be checked against a known label.

Independent re-implementation on public data with synthetic incidents. This page is an explorer: counts show what happens on one sample at the settings you choose. It runs entirely in your browser from precomputed scores and does not reproduce any earlier deployment result.

      How it works
      1. Data. Hourly readings from a real household electricity dataset (a 120-day window per series). A seeded generator injects labelled incidents: spikes, level shifts, slow drifts, stuck values and bursts of missing values. The first 60 days are a calibration window, the last 60 days are shown here.
      2. Scores. Each hour gets an anomaly score from Python code in this repository, using only past data. The baseline is the distance from the global mean in standard deviations. The improved options compare each value with what is normal for that hour of day (seasonal residual), use rolling medians, an EWMA control chart, or an Isolation Forest.
      3. Threshold. The slider picks a percentile of the scores seen in the calibration window, so both detectors are compared at the same alert rate on normal history. Points above the threshold are flagged.
      4. Persistence. With a value above 1, an alert is raised only after that many consecutive flagged hours. This removes isolated blips, but it delays alerts and can miss short incidents such as spikes.
      5. Data-quality rules. Optional checks for missing values, values outside the usual range and values stuck at the same reading. They are added to each detector's flags.
      6. Reading the numbers. An alert is a run of flagged hours. It is a true alert if it overlaps an injected incident and a false alert otherwise. An incident counts as caught if at least one alert falls inside it. Natural events in the real data that were not injected have no label, so they count as false alerts.

      Evaluated results across many series and seeds, with methods and limitations, are in the repository README. The 20% false-positive reduction on the CV is a reported result from an earlier deployment and is not reproduced here.
